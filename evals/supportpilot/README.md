# SupportPilot 固定案例与评测产物

`cases.json` 保存可编辑的固定案例；`runs/` 保存每次运行的独立产物。当前包含 12 个合成案例、14 轮对话，覆盖寒暄、信息补全、启动配置、测试回归、交接报告、跨域检索、证据不足、多轮更正与检索，以及 SP11/SP12 两条由 supervisor 委派到日志专家的案例。案例不包含真实客户信息、私有文档正文或预设的虚构来源链接。

跨域案例根据本地已有文档的主题设计，但本地导入记录不保证当前后端索引可用或一定命中。未知项目案例也不预设 `no_results`，因为向量检索可能返回其他主题的片段。第一版通过人工复核判断适用性，不把“有命中”视为正确。

## 运行

在项目根目录先校验案例，不访问模型或数据库：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_supportpilot.py --validate-only
```

使用已有配置启动后端（检索案例还需要已入库的 Qdrant 和 Embedding 配置）：

```powershell
.\.venv\Scripts\python.exe src/run_service.py
```

在另一个终端执行评测。此命令调用真实后端和模型，会产生正常的模型与 Embedding 用量，并在后端 checkpoint 中保存独立的评测会话：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_supportpilot.py
```

脚本启动时先通过现有客户端请求 `/info`，检查后端连接、认证、Agent 和指定模型，检查超时最多 5 秒。未通过时直接提示启动命令或连接配置，退出码为 `2`，不执行案例或创建结果目录。后端需要一直保持运行；评测 CLI 不会自动启动服务。执行中的错误会在终端显示具体原因，并写入本轮结果。

只跑一个或多个案例：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_supportpilot.py --case SP06 --case SP10
```

可选参数包括 `--base-url`、`--model`、`--timeout`、`--cases` 和 `--output-dir`。默认后端为 `http://127.0.0.1:8080`，Agent 固定为 `dev-issue-agent`，模型默认由服务选择。`--model` 接受服务支持的模型枚举名称（例如兼容服务使用 `openai-compatible`），并非任意厂商模型名。脚本读取根目录 `.env` 中的 `AUTH_SECRET`；已有环境变量优先。每轮总超时默认 90 秒。

每个案例生成新的 `thread_id`，案例内的多轮对话复用该线程；一次评测共享独立的 `eval:` 用户编号。同一轮只调用一次现有 `AgentClient.astream(stream_tokens=False)`，不复制问答或检索逻辑，不自动重试。运行顺序固定；某轮出现执行错误后跳过该案例余下轮次，继续后面的独立案例。规则未通过时仍继续同一案例的下一轮。

退出码：`0` 表示全部案例的自动规则通过，`1` 表示存在未通过或执行错误，`2` 表示参数/案例不合法、后端检查未通过或输出目录已存在，`130` 表示人工中断。退出码 0 不代表答案质量已通过人工复核。

## 留存与报告

默认输出到 `runs/<时间>-<随机编号>/`，拒绝覆盖已有目录：

| 文件 | 内容 |
| --- | --- |
| `cases.json` | 本次实际选中的案例快照 |
| `manifest.json` | 评测编号、案例版本及规范化快照 SHA256、后端地址、请求模型、超时、起止时间、运行状态 |
| `results.jsonl` | 每轮输入、完整消息、答案、thread_id、run_id、工具证据、耗时、规则结果及待复核条件 |
| `summary.json` | 案例及轮次统计、未记录轮次数、自动通过率、待人工复核数量 |
| `report.md` | 中文汇总、每轮问答、工具调用、检索证据及人工复核清单 |

每完成一轮立即追加并刷新 JSONL，更新本地报告。人工中断时保留已完成轮次和 `interrupted` 状态；强制杀进程可能留下 `running` 状态，第一版不自动恢复或续跑。重新运行会创建新的评测目录和会话。时间字段采用 UTC+08:00，耗时使用单调时钟。

`runs/` 已加入 Git 忽略规则：真实答案和证据可能包含私有知识库正文。案例定义和使用说明可以提交；结果由用户选择性留存或分享。

## 评判方式

自动检查最终回答非空、run_id 一致、工具请求与结果匹配、检索策略、每轮最多两次工具调用、工具结果格式、检索服务状态、回答中的 HTTP(S) 链接是否来自同一案例的用户材料或实际检索证据，以及当前 Agent 已知的超时/预算耗尽兜底文本。

这些检查不能证明文本事实正确、引用支持结论、追问合理或模型确实理解了上下文。链接检查是 URL 文本匹配，复杂 URL 写法可能需要人工核对。报告中的质量复核项全部初始为“待完成”，应逐条人工判断并记录理由。尚未接入 LLM 判分或人工复核结论回写；直接编辑 Markdown 不会更新 JSON 汇总。

如需基于已确认的真实索引标注检索期望，可在某轮增加：

```json
{
  "expected_document_ids": ["真实 document_id"],
  "expected_status": "ok"
}
```

`expected_document_ids` 检查指定文档是否都出现在本轮工具返回中；第一版不计算 Recall@K、MRR 或语义正确率。`expected_status` 可取 `ok`、`no_results`、`error`，要求该轮每次检索都符合预期；`error` 只适合另外明确配置的故障演练。现有固定案例没有主动制造服务故障。

## 后续同步飞书文档

本轮只生成本地产物。案例定义、每轮结果和运行信息都有 `schema_version` 或所属版本，可作为同步输入；`report.md` 已按标题、问题、回答、工具证据和复核清单分段。后续发布模块可以读取这些文件，创建并写入飞书文档，无需重新调用 Agent。飞书文档权限、创建写入、报告链接和完成通知将在后续单独实现。
